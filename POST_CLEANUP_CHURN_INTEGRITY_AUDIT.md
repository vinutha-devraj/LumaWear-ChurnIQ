1. **Feature Extraction Line-by-Line (`src/churn/features.js`):**
   - `extractCustomerFeatures()` strictly filters activities by `toId(activity.userId) === toId(userId)`. No activity from customer $A$ can ever enter customer $B$'s feature calculation.
   - 30-day window features (`product_views_30d`, `distinct_products_viewed_30d`, `activity_event_count_30d`) compute exclusively against the remaining 1 activity for `shashi dj`.
2. **Customer Counting Source of Truth (`src/server.js`):**
   - Total Customers across `/api/admin/users`, `/api/churn/portfolio-summary`, `/api/churn/retention-opportunities`, `/api/churn/business-impact`, and `/api/churn/model-health` is queried from `User.find({ role: { $ne: "admin" } })` and deduplicated in-memory using `Map(u._id => u)`.
   - Activities and orders are grouped by `userId` in memory and mapped to the parent customer record. Activities never create user records.
3. **Multi-Layer Recurrence Defense:**
   - `ProductDetailsPage.jsx`: `loggedProductRef` visit guard guarantees at most 1 product view per visit.
   - `StoreContext.jsx`: Reducer deduplication (returns state if `recentlyViewed[0] === productId`) + `useCallback` & `useMemo`.
   - `AuthContext.jsx`: Stabilized callbacks.
   - `Layout.jsx`: `lastLoggedRouteRef` guard prevents repeat `page_view` emissions on re-renders.
   - `server.js`: 2-second backend duplicate shield (`Activity.findOne` within 2s returns `deduplicated: true`).
